# Architecture

The repo at a glance, the one rule that holds it together, and the error model every layer speaks.

## The one rule

**Identity flows one way:** `hooks.server.ts` resolves the session into `locals.user`, the `app/` layout enforces it, routes turn it into an `Actor`, and services scope every query by it. Authorization lives in the service - a route can't forget it. Routes are adapters; logic lives in `$lib/server/<feature>/service.ts`. The full set of invariants lives in [AGENTS.md](../AGENTS.md), which is also the contract AI agents are pointed at.

## The Ctx / Actor pattern

Services never touch `platform.env` or `locals`. They receive:

- **`Ctx`** (`$lib/server/ctx.ts`) - `db` (always-fresh Hyperdrive connection), `dbCached` (up to ~60s stale, falls back to `db` until the second binding exists), `waitUntil` (post-response work), and `close` (ends the Postgres client(s); cron/queue handlers call it when done).
- **`Actor`** - `{ id: string }`, derived from `locals.user` by the route. Scoping every query by the actor doubles as authorization: someone else's row is indistinguishable from a missing one.

Routes build the `Ctx` with `createCtx(platform)`; non-HTTP entries (cron, queues in `src/worker.ts`) use `createWorkerCtx(env, executionCtx)`. This is also why services are trivially testable - see [testing.md](testing.md).

## Errors

One failure shape everywhere: `App.Error` is `{ message, code, id? }`.

- Services throw `AppError(code, message)` - typed codes (`unauthorized`, `forbidden`, `not_found`, `conflict`, `invalid`, `rate_limited`, `limit_reached`, `internal`) that map to HTTP statuses (`$lib/server/errors.ts`).
- Route adapters convert: `catch (e) { httpError(e); }` turns an `AppError` into the proper HTTP error with the standard body and rethrows anything else.
- `handleError` (hooks.server.ts) catches the unexpected rest: logs with a generated error id, returns `{ message: 'Internal error', code: 'internal', id }` - internals never reach the client, and the id links a user report to the log line.

## Scripts

| Script                     | What it does                                                          |
| -------------------------- | --------------------------------------------------------------------- |
| `bun run dev`              | Vite dev server (see [testing.md](testing.md) for the runtime caveat) |
| `bun run preview`          | Build + `wrangler dev`: the real Workers runtime                      |
| `bun run test`             | Migrations, then Vitest: `workers` + `browser` projects               |
| `bun run test:e2e`         | Playwright against `wrangler dev`                                     |
| `bun run check`            | cf-typegen + svelte-check (strict)                                    |
| `bun run lint` / `format`  | Prettier + ESLint                                                     |
| `bun run check:invariants` | Greppable-rule guard (isolate-db, `{@html}`, `s-maxage`, barrels)     |
| `bun run check:secrets`    | Block committed credentials                                           |
| `bun run db:up`            | Start the local Postgres (docker compose)                             |
| `bun run db:generate`      | Drizzle migration from schema changes                                 |
| `bun run db:migrate`       | Apply migrations (local by default, `DATABASE_URL` overrides)         |
| `bun run db:studio`        | Drizzle Studio on the local database                                  |
| `bun run cf-typegen`       | Regenerate `src/worker-configuration.d.ts`                            |
| `bun run i18n:compile`     | Recompile Paraglide messages (runs in `prepare` and `check`)          |
