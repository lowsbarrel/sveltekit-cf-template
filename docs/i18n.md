# i18n (Paraglide)

[Paraglide JS 2](https://inlang.com/m/gerre34r/library-inlang-paraglideJs) compiles `messages/{locale}.json` into tree-shakeable functions - only messages you use ship in the bundle. UI strings come from `import * as m from '$lib/paraglide/messages'` and render as `{m.app_title()}`. Never hardcode UI text ([AGENTS.md](../AGENTS.md) invariant).

## The setup

- **English only, but wired for more.** `locales` is `["en"]`. The plumbing is there so adding a language is config, not a refactor - but nothing presumes a second one, and no half-translated catalog ships.
- Locale resolution comes from the Paraglide **vite plugin** config (`vite.config.ts`) and so applies to the dev server and the production build: cookie → `Accept-Language` → base locale. (The standalone `bun run i18n:compile` CLI emits a default-strategy runtime for typecheck/`check`; the vite build regenerates it with the configured strategy, so the running app always uses the order above.) No URL prefixes, so routes and links stay untouched; switch with `setLocale` from `$lib/paraglide/runtime`.
- Message keys are snake_case. After editing `messages/*.json`, run `bun run i18n:compile` (`check` and `prepare` run it too). `src/lib/paraglide/` is generated and gitignored - never edit it.
- The middleware relies on AsyncLocalStorage - already enabled on Workers via the `nodejs_als` flag, natively available on the Node portability build.

## Adding a message

1. Add the key to `messages/en.json`: `"todo_added": "Added!"`.
2. `bun run i18n:compile`.
3. Use it: `m.todo_added()`.

## Adding a locale

1. Extend `locales` in `project.inlang/settings.json`.
2. Add `messages/<locale>.json`.
3. `bun run i18n:compile`.

**Caveat if you do:** the `(marketing)` group is prerendered, so it is built once, in the base locale. Prerendered pages cannot vary by cookie. To localize marketing you must switch Paraglide to its URL strategy (`/de/pricing`) so each locale gets its own prerendered page. The app itself is server-rendered and localizes per request today.

Legal policy texts are deliberately NOT in the message catalog: a policy for another country under its own law is a different document, not a translation - see [billing.md](billing.md#legal-pages). Their chrome (title, meta description, last-updated line, review notice) still comes from the catalog.
